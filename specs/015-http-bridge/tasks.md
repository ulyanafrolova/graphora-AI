# Tasks: HTTP Bridge Between Frontend Calls and Backend Routes

**Input**: Design documents from `specs/015-http-bridge/`

**Prerequisites**: plan.md, spec.md, research.md (R1–R8), data-model.md, contracts/graph-schema-v8.md,
quickstart.md

**Tests**: Required (spec FR-015, FR-016, constitution VIII). Within each phase, write the tests first and
confirm they fail. `expected.json` files are written by hand from the fixture source, never generated by the
tool.

**Organization**: Phase 2 (schema v8, model, serializer, loader, projection, empty resolver wired into the
build) blocks every story. Then:

- US1 (P1): literal calls matched to literal routes, as heuristic `http_call` edges;
- US2 (P1): path parameters normalized across both languages;
- US3 (P2): literal router prefixes and same-file base constants;
- US4 (P2): dynamic, not found and ambiguous calls recorded as unresolved; other hosts dropped.

Paths are relative to the repository root. Code lives in `backend/src/graphora/`, tests in `backend/tests/`.
Run commands from `backend/`. Keep comments minimal, in the style of the existing adapters (module docstring
with a spec reference, one-line docstrings where not obvious).

**Commits** (one per milestone, pushed right after): `tasks: 015 http bridge` for this file; then
`http bridge: schema v8 and graph plumbing` (Phases 1–2), `http bridge: routes, calls and matching`
(US1–US2), `http bridge: prefixes and unresolved calls` (US3–US4), and a final pass
`http bridge: fixtures, docs and checks` (Phase 7).
