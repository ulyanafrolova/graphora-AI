# Implementation Plan: C# Analysis, Slice 2 — Type References and Project-wide Usings (Schema v5)

**Branch**: `docs/constitution-csharp` (PR #22, issue #19) | **Date**: 2026-11-12 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/008-csharp-type-references/spec.md`

## Summary

Slice 1 links a C# file to every file of each namespace it imports. This slice links it to the files whose types it
actually writes, and makes project-wide usings visible.

What the output gains:

- `type_reference` edges file → file, one per pair, at the first line the type is written; `partial` types and
  conditional usings stay `heuristic`, ambiguity is `unresolved`;
- fewer slice-1 `heuristic` `using` edges: a directive keeps them only when nothing is resolved through it;
- `unresolved_type_names` on C# coverage entries, so names that matched nothing are counted, not hidden.

How it works:

- **Extraction**: type names in explicit grammar positions, plus filtered static-member qualifiers (R1).
- **Lookup**: the compiler's namespace-and-type-name order over the slice-1 index, the file's usings and the
  project's global usings (R2).
- **Project usings**: `global using`, implicit usings from the SDK's own props files (R4), `<Using>` items and the
  nearest `Directory.Build.props`, all read as data (R5).
- **Base library**: a shipped .NET 10 type list tells `List`/`Task` apart from missing names and detects
  ambiguity with repository types (R3).

## Technical Context

**Language/Version**: Python ≥ 3.12, developed on 3.14 (unchanged)

**Primary Dependencies**: unchanged (`tree-sitter==0.25.2`, `tree-sitter-c-sharp==0.23.5`, standard-library
`xml.parsers.expat`). Two new shipped data files generated by scripts that are never run by tests.

**Storage**: unchanged; the store sees schema v5

**Testing**: pytest: golden (`csharp-types` new, three C# fixtures updated), contract (v5 samples), unit (type
extraction, lookup, project usings, props reading, fallback), integration (safety for `Directory.Build.props`,
performance)

**Target Platform**: macOS and Linux, no .NET SDK

**Project Type**: CLI, HTTP API and MCP server in the `backend` package

**Performance Goals**: 1,000 `.cs` files in 20 projects under 30 s (SC-005); lookup cached per
(project, namespace chain, name)

**Constraints**: byte-identical output; no process, no reads outside the root, `<Import>` and `$(…)` never
followed; slice-1 rules unchanged

**Scale/Scope**: references per file are typically tens to hundreds; data files ~1 MB in total

No open questions remain. During planning SC-002 was corrected to be measured on `csharp-types` (R10).
