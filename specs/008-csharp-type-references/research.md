# Research: C# Analysis, Slice 2

Decisions R1–R10, referenced from [plan.md](plan.md) and [data-model.md](data-model.md). Slice-1 decisions
(`specs/007-csharp-analysis/research.md` R1–R11) still hold unless changed here.

## R1. Where type names are read (tree-sitter-c-sharp 0.23.5)

- **Decision**: a name node (`identifier`, `qualified_name`, `generic_name`, `alias_qualified_name`) is a **type
  reference** when it sits in one of these positions, checked against a probe file during planning:
  - field `type` of `variable_declaration`, `parameter`, `property_declaration`, `event_field_declaration`,
    `object_creation_expression`, `typeof_expression`, `cast_expression`, `declaration_pattern`,
    `catch_declaration`, `type_parameter_constraint`, and `nullable_type`/`array_type` element types;
  - field `returns` of `method_declaration` / `delegate_declaration`; field `right` of `as_expression`;
  - children of `base_list` and `type_argument_list` (recursively, so `Dictionary<string, Order>` gives
    `Dictionary` and `Order`);
  - field `name` of `attribute` (also tried with an `Attribute` suffix).

  A name in field `expression` of `member_access_expression` (`Static.Call()`) and the argument of `nameof(…)` are
  **qualifier candidates**: they count only if they resolve to a repository or base-library type and the
  identifier is not declared in the file as a local, parameter, field or property name. They never add to the
  unresolved count.
- Skipped: `predefined_type` (`int`, `string`), names equal to a type parameter of an enclosing declaration,
  `var`, and everything inside `using` directives and namespace names (slice 1 handles those).
- **Rationale**: positions are explicit in the grammar, so no guessing about what is a type. Qualifiers are the one
  syntactically ambiguous case (`order.Total` vs `Order.Create`), so they are filtered against declared names and
  never counted as missing.
- **Alternatives**: every capitalized identifier (many false positives); Roslyn semantic model (needs .NET:
  rejected by constitution I).

## R2. Lookup order (FR-002)

- **Decision**: for a simple name `X` in namespace block `A.B` (file-scoped namespaces count as a block around the
  whole file):
  1. level `A.B`: types `A.B.X` in visible scopes; aliases declared inside `namespace A.B { }`; namespaces imported
     by `using` directives inside that block;
  2. level `A`: same for `A`;
  3. level global: types `X` in the global namespace; file-level aliases and global aliases of the project;
     file-level `using` namespaces plus the project's global usings (explicit `global using`, implicit usings,
     `<Using>` items).

  At each level, types declared directly in that namespace win over imported ones (compiler rule); among imported
  namespaces and the base library, two or more distinct full names → `ambiguous`. Qualified names `P.Q.X`: the
  first segment is replaced through an alias if it is one, then the name is tried as `A.B.P.Q.X`, `A.P.Q.X`,
  `P.Q.X` and as `U.P.Q.X` for each imported namespace `U` (nested types reached through a using). `global::`
  names are tried only as written.
- **Rationale**: this is the C# specification's namespace-and-type-name lookup restricted to what is visible
  without semantic analysis; every step is deterministic over sorted data.

## R3. Base-library type list: `dotnet-types@10.0.0`

- **Decision**: extend `scripts/gen_dotnet_namespaces.py` to also write
  `resolve/data/dotnet_types.txt`: `framework namespace type` per line, from the same `T:` entries of the .NET 10
  reference packs (arity and nested parts dropped, public top-level types only), sorted. A name that matches only
  base-library types gives no edge; a base-library type and a repository type in the same lookup level →
  `ambiguous`. Expected size: about 25,000 lines, 1 MB.
- **Rationale**: needed for FR-012 (do not count `List` or `Task` as missing) and for ambiguity like `Task` vs a
  repository `Task`.
- **Alternatives**: no list (cannot tell `List` from a missing type; every file would report dozens of unresolved
  names); a hand-made short list (incomplete, untestable).

## R4. Implicit usings: `dotnet-implicit-usings@10.0.100`

- **Decision**: ship `resolve/data/implicit_usings.txt` (`sdk namespace` per line). It is generated by a new
  `scripts/gen_implicit_usings.py` that downloads the SDK's own props files at pinned tags and reads their
  `<Using Include>` items under the `ImplicitUsings` condition:
  - `dotnet/sdk` `v10.0.100`: `src/Tasks/Microsoft.NET.Build.Tasks/targets/Microsoft.NET.Sdk.CSharp.props`
    (base: `System`, `System.Collections.Generic`, `System.IO`, `System.Linq`, `System.Net.Http`,
    `System.Threading`, `System.Threading.Tasks`), `src/WebSdk/Web/Targets/Sdk.Server.props` (Web),
    `src/WebSdk/Worker/Targets/Microsoft.NET.Sdk.Worker.props` (Worker);
  - `dotnet/winforms` `v10.0.0`: `Microsoft.NET.Sdk.WindowsDesktop.WindowsForms.props`;
  - `dotnet/wpf` `v10.0.0`: the WPF props, if it defines implicit usings.

  Mapping: every SDK gets the base list; `.Web`, `.Razor`, `.BlazorWebAssembly` add Web; `.Worker` adds Worker;
  `UseWindowsForms` adds WinForms; `UseWPF` adds WPF. The `TargetFrameworkIdentifier != .NETFramework` condition
  on `System.Net.Http` is taken as true (SDK-style projects for .NET).
- **Rationale**: the SDK implements implicit usings as `<Using>` items, so reading the real files keeps the list
  exact and lets the project's own `<Using Remove>` items work the same way.

## R5. `<Using>` items and `Directory.Build.props`

- **Decision**:
  - the `.csproj` reader (`csproj-reader@0.2.0`) also returns `Using` items (`Include`, `Alias`, `Static`,
    `Remove`, conditional flag, position) and the `ImplicitUsings` property (value, conditional flag);
  - `Directory.Build.props`: the nearest one in the project's folder or a parent folder inside the root is read
    with the same reader; its `Using` items, `ImplicitUsings` and `PackageReference` items apply before the
    project's own (project values override, `Remove` applies after both);
  - `$(…)` in `Include` or in the `ImplicitUsings` value → the item or value is ignored;
  - an item or property under any `Condition` makes everything resolved through it `heuristic:
    msbuild_condition`.
- **Rationale**: MSBuild imports `Directory.Build.props` before the project body; using the nearest one matches
  MSBuild's own search, and not following its `<Import>` of a parent keeps the "never follow imports" rule.

## R6. Edges from type references

- **Decision**: new edge type `type_reference` (file → file, or file → `unresolved:dotnet:<name>` for ambiguity),
  `form` `static`, `type_only` false, no `directive`/`alias`; `symbol` = full name of the type first referenced;
  line, column and snippet hash of that first reference (the hash covers the trimmed source line), extractor
  `csharp-adapter@0.2.0`. One edge per (source, target): the confidence is the strongest among the references to
  that target, and the position is the first reference with that confidence. Self-references give no edge.
- **Rationale**: matches the issue's "one edge per file pair at the first reference"; the edge type keeps directive
  facts and usage facts apart (FR-005), so queries can tell "written import" from "used type".

## R7. `using` fallback (clarified)

- **Decision**: each `using` directive (and each global using, project-wide) records whether any reference resolved
  through it. A directive whose namespace or alias resolved at least one reference drops its slice-1 edges to
  repository files; its edges to `dotnet`, `nuget` and placeholders stay. `using static` edges always stay (member
  names are not matched). A global `using` in `GlobalUsings.cs` counts as used when any file of the project
  resolves through it.
- **Rationale**: the clarified rule; keeps extension-method and `var` dependencies visible as `heuristic`.

## R8. Unresolved type names count

- **Decision**: C# coverage entries gain `unresolved_type_names`: the number of distinct simple names in type
  positions (not qualifier candidates) that matched neither a repository type nor a base-library type. No edge
  is created for them.
- **Rationale**: FR-012; they are almost always package types, which cannot be listed without downloading
  packages.

## R9. Schema v5 and consumers

- **Decision**: [contracts/graph.schema.json](contracts/graph.schema.json): `schema_version` 5, edge type
  `type_reference` with its constraints, optional `unresolved_type_names` only on analyzed C# coverage entries.
  Consumers updated in the same PR: model, serializer, loader, queries (links include `type_reference` edges;
  `dependents --symbol` matches their `symbol`), MCP overview (`schema_version` only), store validation, tests and
  all fixtures. The draft accepts the current output of five fixtures (version set to 5) and rejects 9 invalid
  samples.
